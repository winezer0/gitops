# GitOps v0.0.2 设计方案

## 目标与范围

GitOps 在调用进程内完成 HTTPS 和 SSH 仓库探测、克隆、引用解析、检出、工作区验证及凭证测试。运行环境无需安装 Git、OpenSSH 或 Git Credential Manager。保留 GitHub、GitLab、Gitea、Gitee 及自建 Git 服务的标准仓库访问能力。SSH 代理继续延期，收到 SSH 代理配置时返回明确的能力错误。

当前版本通过 processkit 调用系统 Git，缺少 Git 时仅对部分 HTTPS 操作回退到 go-git。SSH 主机凭证测试使用 OpenSSH，稀疏克隆及可选的 Git 凭证助手也依赖外部工具。迁移完成后，运行库只有一条 Go 执行路径。

## 模块划分

| 模块 | 职责 |
| --- | --- |
| 公共客户端 | 保留 `Probe`、`Clone`、`Checkout`、`ValidateCheckout`、`TestCredential`、`TestHostCredential`，统一处理策略、超时、事件与错误 |
| Git 引擎 | 以现有 go-git 依赖为起点，实现远程引用枚举、对象下载、检出及本地工作区校验 |
| HTTPS 与 SSH 传输 | 每次操作使用自己的拨号、认证、代理和信任配置，避免通过可变全局传输配置串用凭证 |
| 凭证与信任 | 显式凭证优先，其他凭证由调用方按仓库作用域提供。加载企业 CA、known_hosts 或固定主机公钥 |
| 克隆编排 | 负责暂存目录、稀疏检出、子模块递归、资源限制和结果发布 |

## 操作语义

- **探测和 ref**：保留现有引用解析优先级，覆盖默认分支、完整分支或标签名、带注释标签及固定提交。区分 ref 不存在与服务端拒绝获取未公开提交。固定提交若无法按请求深度获取，返回明确错误，避免隐式下载完整历史。
- **克隆与子模块**：保留默认深度 1、子模块默认关闭。启用递归后，每层都使用相同深度并检出父仓库 gitlink 指定的提交。解析相对 URL 后重新校验目标并解析凭证。整棵工作区共用取消信号、时间与大小限额，并保留现有递归深度限制。
- **稀疏检出**：保留 `SparsePaths`，明确所选目录、祖先层文件及子模块交集的检出规则，并用现有 cone 行为建立对照用例。将工作区文件范围与网络对象过滤分开验收。首选验证现有 go-git 能否提供所需语义，必要时在引擎内部实现受限检出。实际未实现按需下载时，迁移文档需注明稀疏检出可能下载全部对象，继续限制传输与磁盘用量。若实测影响 TanSpec 的资源预算，将对象过滤列为发布前置条件。
- **工作区**：保留目标根目录限制和已固定提交的复用校验。新克隆先写同卷暂存目录，成功后发布。替换现有目录时保留恢复路径，失败或取消时清理本次产物。裸仓库、部分检出以及索引状态分别验证，检查路径越界、符号链接和 Windows 路径冲突。
- **凭证测试**：仓库级凭证测试走实际读取路径。HTTPS 主机级验证继续使用服务商用户 API。SSH 主机级验证以通过主机密钥校验并完成公钥认证为成功条件，适配不提供交互式 shell 的 Git 主机。

## 传输与兼容边界

- HTTPS 使用 Go HTTP 传输，保留代理和自定义 CA，默认校验证书。对仓库请求与服务商 API 统一执行目标策略，跨源跳转须重新校验目标且不透传原凭证。子模块按各自地址匹配凭证，支持同主机不同项目使用不同凭证。
- SSH 使用 Go SSH 库，支持 `ssh://` 和 SCP 风格地址。显式提供用户名、端口、私钥、可选解密口令和主机公钥信任来源。未知或变更的主机密钥导致失败。由 context 覆盖拨号、握手和会话生命周期。Host 别名和本机私钥按凭证发现规则处理。ProxyJump 和 ProxyCommand 随 SSH 代理能力延期。
- 移除运行路径中的 processkit、外部命令后端以及系统凭证助手集成。`UseCredentialHelpers` 在迁移期可保留字段并在启用时返回配置错误，迁移到现有 `CredentialFor` 或新增按仓库作用域的凭证接口。旧 GCM 验证记录保留其对应版本，v0.0.2 私有 HTTPS 验证改用显式凭证。
- 保留公开错误分类与进度回调。进度由网络、对象写入、检出和子模块阶段产生，进程快照字段在 Go 引擎下为空。日志、诊断和错误统一脱敏。认证、主机校验、取消、超时和能力不支持均直接返回相应错误。

## 凭证迁移与优先级

| 能力 | v0.0.1 | v0.0.2 |
| --- | --- | --- |
| 用户自定义 SSH 私钥 | 支持传入未加密私钥字节，通过系统 OpenSSH 认证 | 必须。保留字节输入并支持显式文件路径。支持使用口令在内存中解锁加密私钥 |
| 用户自定义 GitHub PAT | 支持通过 Token 字段访问 HTTPS 仓库，支持 GitHub 用户 API 验证 | 必须。保留 Token 接口，覆盖 GitHub 私有仓库探测、浅克隆和两类凭证测试 |
| 本机 SSH 私钥发现 | 仓库访问可借用 OpenSSH 的配置和默认密钥 | 推荐纳入首版。调用方主动启用，GitOps 用 Go 读取本机 SSH 配置与私钥 |
| 自动复用本机 GitHub 登录 | 可显式启用系统 Git 已配置的凭证助手 | 可选。通过调用方提供的凭证适配器接入已有登录状态。核心库无需安装 Git、GCM 或 GitHub CLI |
| GitHub SSH Key 和 Deploy Key | 对应的未加密私钥可通过通用 SSH 路径使用 | 继续走通用 SSH 私钥认证。GitHub App 私钥换取安装令牌作为独立可选扩展 |

### 凭证选择

1. 优先使用本次请求显式提供的凭证，其次按规范化后的协议、主机、端口和仓库路径查询调用方凭证。保留现有按主机回调作为兼容入口，限制其适用范围。HTTPS 仓库缺少凭证时可尝试匿名访问，配置了可选凭证适配器时由调用方指定适用仓库。
2. SSH 仅在未匹配显式或已配置凭证且调用方启用发现时读取本机密钥。显式私钥字节与文件路径互斥。显式凭证缺字段、解密失败或认证失败时直接返回对应错误。
3. 子模块按自身地址重新执行主机校验与凭证匹配。跨主机或跨仓库只使用对应作用域授权的凭证。调用方可用同一份授权策略控制凭证测试和正常仓库操作。
4. 主机级凭证测试只使用待验证的凭证，避免其他本机身份掩盖失败。PAT 的用户 API 验证和指定仓库读取权限分别报告。

### 本机 SSH 发现

- 通过 Go 获取当前用户主目录，也允许调用方注入 SSH 配置目录。第一阶段读取用户 SSH 配置中的 Host、HostName、User、Port 和 IdentityFile，按文件顺序匹配并保留多个 IdentityFile 候选。显式 URL 中的用户名和端口优先。没有匹配的密钥文件配置时，再按固定顺序尝试默认名称，例如 id_ed25519、id_ecdsa、id_rsa。
- 支持用户目录展开和受限的 IdentityFile 路径解析。限制候选数量。遇到不支持的路由指令时返回能力错误。Include、Match、SSH Agent 和硬件密钥在独立阶段评估。别名解析后的实际主机和端口必须重新通过目标校验，并用于主机密钥验证。
- 对加密私钥使用调用方提供的口令或按密钥路径查询的口令回调。缺少口令、口令错误、密钥格式错误和服务端拒绝认证分别处理。私钥和口令在内存中使用，事件及日志只记录可公开的错误类别。
- 私钥发现与主机信任分别配置。调用方可显式启用本机 known_hosts 文件，或传入固定主机公钥。服务端应用默认使用自身配置的可信密钥来源。

### 验收增量

- SSH 私有夹具覆盖自定义私钥字节、显式路径、正确口令、缺少口令、错误口令和无效密钥。验证显式凭证失败不会改用本机密钥，并检查两类凭证测试的行为。
- 在 Windows 和 WSL 使用临时用户 SSH 目录，覆盖发现功能默认关闭、默认私钥发现、Host 别名、自定义端口、多候选限制，以及别名目标被策略拒绝的情形。
- 私有 HTTPS 夹具验证 Token 传递、权限错误及不同仓库凭证隔离。GitHub PAT 的私有仓库探测、浅克隆和用户 API 测试使用调用方授权的凭证单独验收。加入账号 API 成功但仓库读取失败的覆盖。

## 实施与验收

1. 先建立兼容用例，验证当前锁定的 go-git 在 SSH、浅层固定提交、稀疏检出和工作区状态上的能力。记录差异并确定是否需要升级依赖或补充引擎逻辑。
2. 实现显式私钥和 PAT、按仓库匹配及本机 SSH 发现。完成按请求隔离的 HTTPS 与 SSH 传输，接通仓库探测、引用读取和两类凭证测试。覆盖私有仓库、错误凭证、缺少凭证、未知及变更的 SSH 主机密钥、自定义 CA、代理及取消超时。
3. 切换克隆、检出和工作区验证。用多层子模块夹具检查深度传递、gitlink 固定、凭证隔离、取消和限额，以及失败后原目录仍可使用。
4. 接入 TanSpec 的仓库检查、密钥测试和 Fetcher，使用其真实请求参数核实稀疏路径、固定提交、递归和进度行为。更新迁移说明与中英文 README。
5. 删除外部执行路径和依赖。在 Windows 与 WSL 的隔离环境中运行预编译测试二进制，验证 PATH 无 Git 和 SSH 时仍可完成全套操作。测试夹具在此前准备或由 Go 生成。另用可记录调用的替身验证运行路径从未启动 Git、SSH 或凭证助手。
6. 用本地 HTTPS、SSH 私有夹具完成必测矩阵，随后通过显式凭证复验已授权的自建 HTTPS 仓库。兼容矩阵分别记录已实测服务、协议、功能、版本及限制。已有系统 Git/GCM 测试结果不计入新版验收。
